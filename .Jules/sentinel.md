# Sentinel Journal

## 2026/03/30 - ワイルドカードパターンの正規表現変換における ReDoS および UI 入力制限の不備

**脆弱性:** ユーザー定義の URL パターンに連続するワイルドカード (`***`) が含まれる場合、`.*.*.*` に変換され大量のタブ照会時に指数関数的なバックトラック (ReDoS) を引き起こすリスクが存在していた。また、サイドパネル UI 経由でのターゲット保存処理において、JSON インポート時と同等の入力長・件数制限が適用されていなかった。
**学び:** インポート機能で防御策を設けていても、UI フォーム側の入力バリデーションが不十分であれば多層防御の壁が崩れる。また、ユーザー定義文字列から動的に生成する正規表現には、連続するワイルドカードの正規化やキャッシュ容量の上限化を組み合わせる必要がある。
**予防策:** 動的正規表現生成時には `*+` などの重複ワイルドカードを単一 `*` へ事前に統合し、すべてのデータ入力ポイント（UIモーダル・ファイルインポートの両方）で一貫した境界条件チェックを実施する。

## 2026/03/30 - JSONインポートにおける境界値・入力長制限の不足

**脆弱性:** 設定データのインポート処理 (`importData`) において、インポートする要素数や文字列長に対する上限チェックが不十分であり、極端に巨大なデータ構造や超長文文字列が入力された場合にブラウザのメモリ枯渇や UI フリーズ（DoS）を引き起こす可能性が存在していた。
**学び:** クラッシュやフリーズを引き起こすデータはローカルストレージや拡張機能の処理パフォーマンスに深刻な影響を与えるため、非構造化 JSON や外部入力を取り込む部分には明示的な境界値（要素数最大100件、文字列最大100〜500文字）を課す多層防御が不可欠。
**予防策:** データの構造チェック（型チェック）だけでなく、必ずデータの長さや深さ、サイズに対する境界条件バリデーションを厳格に行う。

## 2026/03/30 - クラウド同期データ（sync storage）に対するスキーマ検証不足

**脆弱性:** `chrome.storage.sync` を経由した端末間同期処理 (`syncFromCloudIfNeeded` や `chrome.storage.onChanged`) において、受信用データに対するスキーマ検証や入力長制限の適用が不十分であり、他の端末や同期ストレージから不正・超長大・構造不備なデータを受信した際に `chrome.storage.local` が汚染され DoS やUI例外が引き起こされるリスクが存在していた。
**学び:** ファイルインポートやUIモーダルだけでなく、バックグラウンドのクラウド同期機能も外部入力境界の1つとして捉える必要がある。非信頼データ（同期ストレージ経由のデータ含む）をローカルストレージやアプリケーション状態に反映する前に必ずスキーマと境界値を検証することが不可欠。
**予防策:** 設定やターゲットデータの入力ポイント（UI・ファイル・ペースト・クラウド同期）すべてで共通の検証関数 (`validateImportData`) を通し、不正なデータを保存・適用前に安全に破棄する。
